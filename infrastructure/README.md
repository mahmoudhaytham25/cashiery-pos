# Infrastructure — Cashiery POS on AWS

Minimal Terraform/Terragrunt setup: **one EC2 instance** that pulls pre-built
images from **ECR** and runs `docker compose`. On every push to `main`, CI
diffs the changed paths and triggers a **CodeBuild** build that clones the
repo, builds+pushes images for the changed services (`backend/`,
`frontend/`), then redeploys the box over SSM — no AWS keys stored anywhere
(GitHub OIDC). The nginx frontend is the only public surface (`:3000`); it
proxies `/api` to the backend, which talks to Postgres inside the compose
network.

```
infrastructure/
├── root.hcl                  # region + aws_profile + shared inputs + provider gen
├── live/dev/                       # one terragrunt.hcl per unit, wired by `dependency`
│   ├── ecr/terragrunt.hcl          #   (no deps)
│   ├── codebuild/terragrunt.hcl    #   deps: ecr + compute
│   ├── compute/terragrunt.hcl      #   deps: ecr
│   └── ci/terragrunt.hcl           #   deps: codebuild
└── modules/
    ├── ecr/        # backend/frontend image repos + lifecycle
    ├── codebuild/  # parameterized build project (buildspec.deploy.yml inlined)
    ├── compute/    # SG, instance IAM role, EC2, EIP, secrets, user_data
    └── ci/         # GitHub OIDC provider + deploy trigger role
```

`terragrunt run-all` resolves the dependency graph — `apply`/`destroy` run in
the right order. `plan`/`validate` work before the first real apply thanks to
`mock_outputs` on each dependency.

## One-time setup

1. Set `region` and `aws_profile` in `infrastructure/root.hcl`.
2. ```bash
   cd infrastructure/live/dev
   terragrunt run-all init
   terragrunt run-all apply
   ```
   (or apply one unit at a time in order: ecr → codebuild → compute → ci)
3. Wire the outputs into GitHub (**Settings → Secrets and variables → Actions**):

   | Terraform output (unit)      | GitHub entry        | Kind   |
   |------------------------------|---------------------|--------|
   | `github_deploy_role_arn` (ci) | `AWS_DEPLOY_ROLE_ARN` | secret |
   | `project_name` (codebuild)    | `CODEBUILD_PROJECT`   | variable |
   | *(your region)*              | `AWS_REGION`          | variable |

4. Push to `main` — the `deploy` CI job diffs the push and calls
   `codebuild start-build` with `CHANGED_SERVICES` + `IMAGE_TAG`. The
   buildspec clones the repo at that SHA, builds+pushes each changed image
   (`<sha>` + `latest`), then sends an SSM command that `git pull`s the box,
   pins `IMAGE_TAG` in its `.env`, and `compose pull && up -d`s it.

First boot: `terragrunt output app_url` in `live/dev/compute`, wait ~3 min,
check `/var/log/cashiery-bootstrap.log` via `aws ssm start-session --target
<id>` (no SSH key needed; or set `ssh_cidr` + `key_name` in
`live/dev/compute/terragrunt.hcl` for port 22).

## Secrets

`JWT_SECRET` and `POSTGRES_PASSWORD` are generated by Terraform
(`random_password`), written to `/opt/cashiery-pos/.env` (chmod 600), and
exposed as sensitive outputs (`terragrunt output jwt_secret`). They live in
state — move to the encrypted S3 backend (commented block in the root
`root.hcl`) before sharing.

## Deploying a new release

Just push to `main` — the `deploy` job handles it. To pin a specific commit
on first boot instead of `latest`, set `image_tag = "<sha>"` in
`live/dev/compute/terragrunt.hcl` — changing user_data replaces the instance
(fresh box, empty DB volume).

## Cost note

t3.micro + 20 GB gp3 + EIP + ECR ≈ ~$10/mo (t3.micro is free-tier eligible
year one). EIP is free while attached to a running instance —
**`terragrunt destroy` when done**; an unattached EIP bills hourly.
